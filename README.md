# WCH CH32F: development platform for [PlatformIO](https://platformio.org)

CH32F series are industrial-grade general-purpose microcontrollers by
[WCH](https://www.wch.cn/) based on the Arm Cortex-M3 core. CH579 is a BLE
microcontroller of WCH based on the Arm Cortex-M0 core.

This platform is modelled on [platform-ch32v](https://github.com/Community-PIO-CH32V/platform-ch32v),
the PlatformIO platform for the RISC-V MCUs of WCH.

## Supported chips

| Series   | Chips | Core | Startup class |
|----------|-------|------|---------------|
| CH32F103 | C6T6, C8T6, C8U6, R8T6 | Cortex-M3 | - |
| CH32F203 | C6T6, K8T6, C8T6, C8U6 | Cortex-M3 | `CH32F20x_D6` |
| CH32F203 | CBT6, RBT6, RCT6, VCT6 | Cortex-M3 | `CH32F20x_D8` |
| CH32F205, CH32F207 | RBT6, VCT6 | Cortex-M3 | `CH32F20x_D8C` |
| CH32F208 | RBT6, WBU6 | Cortex-M3 | `CH32F20x_D8W` |
| CH579    | M (QFN48), F (QFN28) | Cortex-M0 | - |

Each chip has a generic board definition `generic<chip>`, e.g.
`genericCH32F103C8T6` or `genericCH579M`, generated by
`misc/scripts/gen_boarddefs.py`.

## Frameworks

All frameworks come from the [framework-wch-arm-sdk](https://github.com/zuyih/framework-wch-arm-sdk)
package, the CH32F10x, CH32F20x and CH579 EVT of WCH ported to GCC.

* `noneos-sdk`: WCH Standard Peripheral Library without OS
* `freertos`: FreeRTOS V10.4.6 on top of the NoneOS SDK (CH32F only)
* `rt-thread`: RT-Thread 3.1.3 on top of the NoneOS SDK (CH32F only)

## Upload and debug

`upload_protocol = wch-link` (default for CH32F) and `upload_protocol = cmsis-dap`
use OpenOCD from [tool-openocd](https://github.com/zuyih/tool-openocd)
(Linux x86_64 only for now) with `interface/cmsis-dap.cfg` and
`target/ch32f1x.cfg`, which programs the flash with the `wch_arm` driver (the
fast page programming of the CH32F), or `target/ch579.cfg` with the `ch579`
driver. The WCH-Link(E) is a CMSIS-DAP probe in ARM mode, switch
it with `wlink mode-switch` or the WCH-LinkUtility. `wch-link` only connects to
a WCH-Link in DAP mode (USB ID `1a86:8012`, or `1a86:8011` for the HID mode of
the WCH-DAPLink), `cmsis-dap` to any CMSIS-DAP probe, e.g. a DAPLink.

With several probes connected, select one by its serial number (one argument
per line):

```ini
upload_flags =
  -c
  adapter serial LU_2022_8888
```

`upload_protocol = isp` (default for CH579, also available for CH32F) uses
`wchisp` and the USB bootloader of the chip. Upload and debug of the CH579
through a CMSIS-DAP probe need its 2-wire debug interface, which has to be
enabled in the configuration of the chip first, e.g. with WCHISPStudio.

`debug_speed` also sets the adapter speed for uploads with OpenOCD.

## CH579 and the BLE library

The BLE and network libraries of the CH579 EVT are compiled by ARM
Compiler 5. They can be linked with GCC after rewriting them with
`tools/fix_armcc_lib.sh` of framework-wch-arm-sdk, see
`examples/ble-peripheral-ch579`. The builder compiles CH579 code with
`-fshort-enums` to match the enum size of these libraries.

The system clock of the CH579 is set up by `SystemInit()` (32 MHz) and
`SetSysClock()`; `FREQ_SYS` has to match it. `board_build.f_cpu` and
`board_build.clock_source` do not apply to the CH579.

## Board options

| Option | Default | Description |
|--------|---------|-------------|
| `board_build.f_cpu` | 72 MHz (CH32F10x), 144 MHz (CH32F20x) | System clock |
| `board_build.clock_source` | `hsi+pll` | `hsi`, `hse`, `hsi+pll` or `hse+pll` |
| `board_build.stack_size` | 2048 | Stack size in the linker script |
| `board_build.ldscript` | generated | Custom linker script |
| `board_build.startup` | built-in | Custom startup file |
| `board_build.use_builtin_startup_file` | yes | Build the startup file of the SDK |
| `board_build.use_builtin_system_code` | yes | Build `system_ch32f*.c` of the SDK (CH32F) |
| `board_build.use_builtin_debug_code` | yes | Build `debug.c` of the SDK (CH32F) |
| `board_build.cpp_support` | yes | Run C++ constructors at startup |
| `board_build.use_lto` | no | Link time optimization |
